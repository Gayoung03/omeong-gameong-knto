# 카카오 로컬 데이터 대체 가능성 평가

작성일: 2026-09-08 · 작성: viowlet · 상태: **평가만, 결정 없음**

카카오 로컬 API 이용정책이 검색 결과의 저장을 금지한다는 사실이 확인되어, 현재 DB에서
카카오에 의존하는 데이터가 무엇이고 다른 출처로 대체할 수 있는지를 조사했다.
**이 문서는 판단 재료다. DB 데이터를 지우거나 바꾸는 결정은 팀이 한다.**

---

## 1. 카카오 이용정책 (확인된 것)

- 개발자 FAQ: "응답받은 결과 데이터를 별도로 저장하여 사용하는 것은 허용하지 않으며, 실시간 호출만 가능하다."
- 카카오 담당자 공식 답변 (데브톡, 2026-08-21): **저장 허용** = 장소 ID, 장소명, place_url, 사용자가 정한 방문 순서.
  **저장 불가** = 카테고리, 좌표, 주소, 전화번호 등 나머지 검색 결과 필드. 카테고리는 "화면 노출 시점에 실시간 호출"로.
  좌표를 호출 시점 계산에 쓰는 것은 가능.
- 담당자 답변 (2026-08-26): 임시 저장도 원칙적으로 금지. ID만 저장하고 표시 정보는 실시간 호출하는 방식은 허용.
- 운영정책 원문 페이지는 접속이 되지 않아 조문 번호는 확인하지 못했다(FAQ 인용은 데브톡 스레드 기준).
- 무료 한도: 로컬 API 하루 10만 건, 카카오 전체 통합 월 300만 건.

## 2. 현재 DB의 카카오 의존 범위 (팀 RDS, 2026-09-08 조회)

| 구분 | 건수 | 카카오에서 온 필드 | 비고 |
| --- | --- | --- | --- |
| 카카오 **단독** 출처 장소 | **598** (cafe 503 · restaurant 44 · accommodation 30 · pet_service 21) | 이름·카테고리·좌표·전화(531) · 장소 ID·place_url | **주소·이미지 없음.** 정책은 598건 전부 `unknown`이고 내용 없음(자리표시자) |
| 카카오 + 다른 출처 장소 | 17 | 일부 필드 | KCISA·비짓제주 값으로 대체 가능 |
| 지오코딩 좌표 (2026-08-31 결정) | 요청·숙소 좌표, 명소 시드 28곳(미적용) | 좌표 | 카카오 주소·키워드 검색 결과 |
| Phase 2 `cuisine` | 0 (스크립트만, 미적용) | 카테고리 2단계 | 저장 불가 항목에 정확히 해당 |

주목할 점: **DB의 카페 518곳 중 503곳이 카카오 단독**이다. 카페 카테고리 자체가 카카오에 서 있다.
반면 이 598곳은 반려동물 정책 정보를 전혀 갖고 있지 않아, 재설계 이후 추천에서는
"확인 필요" 후보로만 쓰인다(챗봇·검색 노출은 별개).

## 5. 정밀 확인을 위해 남은 실측 (계정·파일 필요)

1. 공공데이터포털에서 **행안부 일반음식점·휴게음식점·숙박업 제주 데이터** 내려받아 598곳과 이름+거리 매칭 → 실제 커버리지 %.
2. **한국문화정보원 2025-03 갱신판** 내려받아 598곳 대조 → 정책까지 채워지는 건수.
3. **juso 좌표 API** 승인키로 명소 28곳 지오코딩 → 현재 좌표와 오차 비교.
4. 카카오 데브톡에 **우리 사례**(공모전용 비영리, 장소 마스터 병합, 지오코딩 좌표) 문의 → 해석 확정.

1·2는 팀 공공데이터포털 계정으로 파일을 받으면 스크립트로 바로 측정할 수 있다(매칭 스크립트는 비짓제주 실측에 쓴 것을 재사용).

## 6. 이 평가에서 하지 않은 것

- DB 데이터 삭제·수정. Phase 2 스크립트 적용도 없음.
- 카카오 임포트(2026-08-12)와 지오코딩 좌표 저장(2026-08-31) 결정의 변경. 팀 논의 대상.
