# 챗봇 답변 생성 — 성능·비용·검색 정확도 측정 보고 (2026-09-13)

대상은 **챗봇 답변 생성 한 갈래**입니다(`app/integrations/llm/chat.py`). 앱 전체
응답시간이나 동시접속은 재지 않았습니다(§9).

이 문서의 모든 숫자는 **실제 OpenAI 호출 440회, $3.60** 에서 나왔습니다. 원자료는
`tmp/chat-measure-*.json` 이고, 각 파일의 `meta` 에 코드 버전·대상 DB·실행 시각·
반복 횟수·단가 확인일이 함께 들어 있습니다.

## 1. 요약

**정확도를 고쳤고, 비용은 19~20% 줄었고, 첫 글자는 0.6~1.0초 느려졌습니다.**
그리고 **두 모델의 정확도 차이가 없어졌습니다.**

| | gpt-4o-mini | gpt-4o |
| --- | --- | --- |
| 질문당 비용 | $0.000952 → **$0.000760** (−20%) | $0.016175 → **$0.013167** (−19%) |
| 첫 글자까지 | 1.42s → 1.99s | 1.44s → 2.41s |
| 전체 완료 | 2.42s → 2.43s | 2.67s → 3.03s |
| 규정 문항 정확도 | 문항별 0~3/4 → **전부 4/4** | 2~4/4 → **전부 4/4** |

측정은 문항 16개(규정 6 · 장소 6 · 탈출구 4) × 모델 2 × **4회**, 각 조건 n=64 입니다.
두 모델의 비용 차이는 여전히 **17.3배**지만, **이 문항들에서는 답이 같아졌습니다.**

첫 글자가 느려진 것은 값을 치른 결과입니다 — 운송 규정 질문에서 목록을 우리가
붙이느라 답을 다 받은 뒤에야 내보내기 때문입니다(§6-나).

## 2. 어떻게 쟀나

```bash
make chat-measure SET=rules MODELS=gpt-4o-mini,gpt-4o REPEAT=4
```

- 프로덕션 코드를 고치지 않고 잽니다. `chat_module.OpenAI` 라는 **이름만** 추적
  래퍼로 바꿔 usage 청크를 옆에서 기록합니다.
- 시간은 둘로 나눕니다 — **첫 글자까지**와 전체 완료. 엔드포인트가 SSE 로 조각을
  흘려보내므로 사용자가 기다리는 시간은 앞쪽입니다.
- 대상 DB 는 **팀 dev RDS** 입니다. 로컬 씨앗은 장소 4건의 권역이 챗봇 어휘 밖이라
  장소 질문이 전부 0건이 됩니다.
- 질문·실제 검색 인자·도구가 돌려준 값·답변 원문·판정을 전부 JSON 에 남깁니다.
  확인하러 갈 때마다 다시 호출해 요금을 내지 않기 위해서입니다.

**자동 판정은 오답률이 아니라 의심 신호입니다.** 문자열 대조뿐이라 약칭이면 걸리고,
아무 회사도 언급하지 않으면 오히려 통과합니다. 아래의 "4회 중 몇 회"는 전부
**답변 원문을 직접 읽어** 센 것입니다.

| ① 12kg — 위탁 가능 4곳을 다 말함 | **0/4** | 3/4 |
| ① 위탁 제도 없는 3곳을 구분해 밝힘 | **0/4** | 4/4 |
| ② 화물칸 — 4곳 다 말함 | **1/4** | 4/4 |
| ② 제도 없는 3곳 구분 | **1/4** | 2/4 |
| ③ 복서 — 근거 없이 분류하지 않음 | **0/4** | **0/4** |

**DB 는 병목이 아닙니다.** 도구(DB 조회)에 쓴 시간이 전체의 0.4~1.1% 입니다. 나머지

**입력이 비용의 85~95% 이고, 그 입력의 89% 가 매번 같은 고정 프롬프트였습니다.**
0라운드가 prompt 4,874 토큰을 태워 completion 21 토큰(도구 호출 하나)을 받고 있었습니다.

## 4. 찾은 오류와 원인

원인을 셋으로 나눴습니다. **한 오류에 원인이 둘인 경우가 있습니다.**

### ㉮ 데이터가 있는데 도구가 건네지 않음

- **견종**: `transport_restricted_breeds` 에 152건(맹견 72·단두종 80)이 있고 복서도
  대한항공·아시아나·진에어에 `applies_to=cargo` 로 들어 있는데,
  `search_transport_rules` 가 이 테이블을 **읽지 않았습니다.** 앱의 `/guides` 는
  읽습니다. 그래서 두 모델 8회 전부 지레짐작했습니다.
- **로컬 씨앗 누락**: `seed_dev.py` 가 견종을 심지 않아 로컬 0건 / RDS 152건이었고,
  같은 질문이 다른 데이터 위에서 돌았습니다.

### ㉯ 검색 조건·검색 코드

- **`pet_weight_kg` 에 0 을 받아들임**: 스키마가 `minimum: 0` 이라 `gpt-4o-mini` 가
  무게를 모르는 질문에 0 을 지어넣은 실행이 있었습니다(4회 중 1회). 0kg 은 모든
  상한을 통과해 **전 회사가 "가능"으로 뒤집힙니다.**
- **무게 없는 질문에 결론을 안 만들어 줌**: 무게가 있을 때는 회사별 결론 문장을
  완성해 건넸는데, 없으면 규정 원본만 주고 분류를 모델에게 맡겼습니다. 에어부산
  오분류가 정확히 그 자리에서 났습니다.
- **여객선에 없는 제도를 붙임**: 여객선 5건은 `cargo_allowed` 가 전부 NULL 인데
  결론에 "위탁 가능 여부 미확인"이 붙어, 배에 없는 제도를 있는 것처럼 읽혔습니다.
- **어휘 밖 값 생성**: `gpt-4o-mini` 가 `region="제주국제공항"` 을 보낸 실행이
  1/24 있었습니다. 다만 검색 함수가 "다음 중에서 고르세요"라고 돌려주고 모델이
  다시 골라 회복했습니다 — **재검색(B7)이 실제로 값을 한 설계**입니다.

### ㉰ 모델이 받은 것을 제대로 옮기지 않음

- "모두 ~하다"로 묶기. 도구가 회사마다 결론을 완성해 건넸는데도 `gpt-4o-mini` 가
  "모든 항공사가 45kg까지"로 묶었습니다.
- 조회된 회사 중 일부만 나열하고 닫기("기타 항공사들은 실을 수 없어요").
- **"확인 안 됨"을 "제한 없음"으로 바꿔 적기** — 수정 후에도 남아 있습니다(§8).

## 5. 고친 것과 전후 비교

커밋 `9733ed7` · `20c5eae` · `b233155`.

- `search_transport_rules(breed_name=...)` 가 회사별 제한 목록과 대조합니다.
  **"목록에 있음" / "목록에는 없음" / "목록이 없어 확인 안 됨" 셋을 절대 섞지
  않습니다.** 셋째를 "가능"으로 옮기면 없는 규정을 만들기 때문입니다.
- 표기 차이를 대표 이름으로 모읍니다(대한항공 `불독` / 아시아나 `불도그`).
  부분 일치는 쓰지 않습니다 — `불독` 이 `불테리어` 에 걸리면 반대로 틀립니다.
- 회사별 결론을 **무게를 안 넣어도** 만듭니다. 동반 불가인 곳에는 "가능한 곳과
  섞지 말고 함께 밝힐 것"이라는 지시를 결론에 함께 담습니다.
- `pet_weight_kg` 는 0 이하를 "말하지 않은 것"으로 칩니다(스키마·코드 두 겹).
- 여객선은 `동승` 한 칸만 냅니다.
- `seed_dev.py` 가 견종을 함께 심습니다.

## 6. 속도·비용 최적화

측정에서 나온 낭비는 하나였습니다. **0라운드가 답변용 규칙까지 함께 태우고
있었습니다** — 말투·서식·답변 길이·판정 옮기기는 "어떤 도구를 부를지" 결정에
쓰이지 않습니다.

적용(`53b5483`): 0라운드에만 짧은 안내(도구 고르는 규칙 · 검색하지 않는 것 ·
어휘 목록)를 보냅니다. **답변 라운드의 프롬프트는 한 글자도 바뀌지 않았습니다**
(`build_system_prompt()` 의 출력이 이전과 완전히 같다는 것을 확인하고 넣었습니다).

| 문항 묶음 | gpt-4o-mini | gpt-4o |
| --- | --- | --- |
| 규정 | $0.001079 → $0.000914 (−15%) | $0.018405 → $0.015056 (−18%) |
| 장소 | $0.000953 → $0.000784 (−18%) | $0.016393 → $0.012825 (−22%) |
| 탈출구 | $0.000826 → $0.000618 (−25%) | $0.014314 → $0.010614 (−26%) |

품질은 탈출구 32/32 유지, 장소 검색 인자 mini 23/24 → **24/24**, `gpt-4o` 는 규정
전 문항 유지. `gpt-4o-mini` 의 화물칸 "제도 없는 3곳 구분"만 4/4 → 2/4 로
내려갔는데, 4회 표본이고 같은 실행에서 배편 문항은 2/4 → 3/4 로 올랐습니다.

### 공짜가 아닙니다 — 캐시를 데우던 이득이 사라집니다

프롬프트가 둘로 갈리면 0라운드가 답변 라운드의 캐시를 데워 주던 효과가 없어집니다.

| | 첫 질문(앞뒤로 요청 없음) | 이어지는 질문 |
| --- | --- | --- |
| 기존 | $0.00114 | $0.00079 |
| 0라운드 분리 | $0.00118 (**+4%**) | $0.00063 (**−20%**) |

**트래픽이 꾸준하면 이득이고, 완전히 뜸하면 근소하게 손해입니다.** 위 표의
17~19% 절감은 질문이 연달아 들어오는 조건에서 잰 값입니다.

그리고 `SEARCH_RULES` 는 `RULES` 와 내용이 겹칩니다 — 규칙을 고칠 때 양쪽을 함께
고쳐야 합니다. 이 절감이 그 부담을 치를 값어치가 있는지는 팀이 정할 몫입니다.

### 나. 운송사 목록을 모델이 옮겨 적지 않게 했습니다

위 표를 낸 뒤에도 `gpt-4o-mini` 는 **조회된 회사를 빠뜨렸습니다** — 7곳 중 3곳만
쓰고 `"위 항공사들은 실어도 되니"` 로 닫는 식입니다. 옮겨 적다 빠뜨리는 것이
문제이므로 **옮겨 적는 일을 안 시켰습니다.** 결론 문장은 이미 파이썬이 만들어
두었으니(`_carrier_conclusions`) 그대로 붙입니다. 모델은 앞머리 한두 문장만 씁니다.

**모델이 그 지시를 무시하고 목록을 또 쓰는 것까지 확인했습니다.** 같은 목록이 두
번 나왔습니다. 지시를 안 따르는 것이 애초의 문제라 지시를 더 세게 적는 것은 답이
될 수 없어서, **결과를 우리가 잘라냅니다**(`_lead_in` — 첫 글머리표부터 버립니다).

여기에 하나가 더 필요했습니다. `gpt-4o-mini` 는 이어지는 질문에서 `breed_name` 을
빼고 다시 조회합니다. 예전에는 답변 문장이 흐려지는 정도였는데, **목록을 우리가
붙이게 된 뒤로는 그 목록이 "위탁 가능"이라고 말해 더 위험해졌습니다.** 그래서
대화 글에서 우리 목록에 있는 견종 이름을 찾아 이어받습니다(`find_known_breed`).
지어내는 것이 아니라 `transport_restricted_breeds` 의 이름과 글자를 맞추는 것입니다.

| 확인 항목 | mini 전 | mini 후 | 4o 전 | 4o 후 |
| --- | --- | --- | --- | --- |
| 12kg — 위탁 4곳 다 말함 | 1/4 | **4/4** | 4/4 | 4/4 |
| 12kg — 제도 없는 3곳 구분 | 2/4 | **4/4** | 4/4 | 4/4 |
| 화물칸 — 4곳 다 말함 | 1/4 | **4/4** | 4/4 | 4/4 |
| 화물칸 — 제도 없는 3곳 구분 | 2/4 | **4/4** | 4/4 | 4/4 |
| 배편 — 동승 불가 항로 밝힘 | 3/4 | **4/4** | 4/4 | 4/4 |

**값을 치렀습니다.**

- **첫 글자가 느려집니다.** 목록을 붙이는 질문은 답을 다 받은 뒤에야 내보냅니다 —
  중간에 흘려보내면 잘라낼 것이 이미 화면에 남습니다. 전체 평균으로 mini 1.42s →
  1.99s, 4o 1.44s → 2.41s 입니다.
- **답변이 사무적입니다.** 목록이 줄 세운 형태로 고정되고, 모델이 덧붙이던
  `"상한이 다른 곳보다 낮아요"` 같은 말이 사라집니다.
- **길이 규칙을 우리가 어깁니다.** 프롬프트는 여덟 문장을 넘지 말라고 하는데,
  견종 질문에서 항공사 7곳 + 항로 5개를 붙이면 12줄이 됩니다.

`RENDER_TRANSPORT_LIST = False` 로 끌 수 있습니다.

### 검토했지만 적용하지 않은 것

- **재검색(B7) 없애기** — 라운드를 줄여 도구 스키마를 뺄 수 있지만, 장소 측정에서
  모델이 어휘 밖 값을 보냈다가 **재검색으로 회복한 사례**가 실제로 있었습니다.
  없애면 그 질문이 0건 답변이 됩니다.
- **도구 결과에서 `source_url` 빼기** — 데이터에 값이 없어 애초에 나가지 않습니다.
- **DB 튜닝** — 전체 시간의 1% 미만이라 얻을 것이 없습니다.

## 7. 월 질문 수별 비용 (수정 후 기준)

월 질문 수를 몰라 세 구간으로 냅니다. 세 문항 묶음의 평균입니다.

| 월 질문 수 | gpt-4o-mini | gpt-4o | 차액 |
| --- | --- | --- | --- |
| 1,000 | $0.79 | $13.11 | $12.32 |
| 10,000 | $7.91 | $131.09 | $123.18 |
| 100,000 | $79.12 | $1,310.88 | $1,231.76 |

이 표는 **질문 한 건에 대화 이력이 없다고 보고 잰 값**입니다. 실제 대화는 지난
메시지를 최대 20개까지 함께 보내므로(`HISTORY_LIMIT`) 대화가 길어질수록 비싸집니다.

## 8. 아직 못 고친 것 · 가설로 남긴 것

1. **"확인 안 됨"을 "제한 없음"으로 바꿔 적는 것** — 도구가 "에어부산은 단두종
   목록이 공개되지 않아 확인 안 됨"이라고 건넸는데 `gpt-4o` 가 4회 중 1회
   "제주항공·이스타·티웨이는 단두종 제한이 없고"로 옮겼습니다. **도구를 고쳐도
   남은 문제**입니다.
2. **무게를 모르는 채 기내 상한을 권하는 것** — 복서(보통 25~30kg)에게 "기내 9kg
   까지 되니 제주항공을 추천해요"라고 쓴 답변이 있었습니다. 프롬프트가 금지한
   문장이고 두 모델 다 냈습니다.
3. ~~이어지는 대화에서 `gpt-4o-mini` 가 견종을 잊습니다.~~ **닫았습니다**(§6-나).
   모델은 여전히 `breed_name` 을 빠뜨릴 수 있지만, 대화 글에서 견종을 찾아
   이어받으므로 답은 같아집니다.
4. ~~오션비스타(삼천포) 항로가 배편 답변에서 자주 빠집니다.~~ **닫았습니다** —
   목록을 우리가 붙이므로 조회된 항로가 빠질 수 없습니다.
5. **`gpt-4o-mini` 답변에 일본어 글자가 섞인 실행**이 1회 있었습니다
   ("기내 가능(상한 9kg)ですが").

6. **목록이 길어졌습니다.** 견종 질문에서 항공사 7곳 + 항로 5개가 붙어 12줄이
   됩니다. 프롬프트의 "여덟 문장" 규칙을 **우리가 어기고 있는** 셈입니다.
   질문이 항공만 물었는데 여객선까지 조회되는 것도 겹칩니다.

1·2번은 **모델이 규칙을 따르지 않는 문제**로 분류합니다. 도구를 고쳐 재측정한
뒤에도 남았기 때문이고, 앞머리 문장은 아직 모델이 쓰는 자리라서입니다.
다만 "비싼 모델로 바꾸면 닫힌다"는 아직 **가설**입니다 — 둘 다 `gpt-4o` 도 냅니다.

## 10. 팀이 정할 것

### C1. 운영 기본 모델

**측정 중에 결론이 뒤집혔습니다.** 목록을 모델이 옮겨 적지 않게 한 뒤로
`gpt-4o-mini` 가 규정 문항 전부에서 `gpt-4o` 와 같아졌습니다.

| | gpt-4o-mini | gpt-4o |
| --- | --- | --- |
| 비용 | 1배 | **17.3배** |
| 규정 질문 정확도 | **전 문항 4/4** | 전 문항 4/4 |
| 장소 검색 인자 | 23/24 | 24/24 |
| 탈출구 | 16/16 | 16/16 |
| 속도 | 차이 확인 못 함 | 차이 확인 못 함 |

**이 문항들에서 재본 한, 비싼 모델을 쓸 근거가 남아 있지 않습니다.**
`gpt-4o-mini` 로 가고 아낀 돈을 다른 데 쓰는 쪽을 제안합니다.

**다만 이 결론의 범위를 좁게 읽어야 합니다.** 같아진 이유는 모델이 좋아져서가
아니라 **틀리던 일을 모델에게서 뺐기 때문**입니다. 그 일을 아직 모델이 하는 자리
— 앞머리 문장, 장소 추천 문장, 여기서 재지 않은 질문들 — 에서는 차이가 그대로
있을 수 있습니다. 실제로 장소 검색 인자는 여전히 23/24 대 24/24 입니다.

### 결정에 필요한데 없는 숫자

**월 질문 수.** 지금 결론대로면 월 1만 건에 약 $8 이라 어느 구간이든 부담이
아니지만, 뒤집혀 비싼 모델로 가면 이 숫자가 바로 필요해집니다.

### 함께 정할 것 둘

- **0라운드 분리를 유지할지** — −19~20% 대 규칙 두 벌 관리(§6-가).
- **목록을 우리가 붙이는 것을 유지할지** — 정확도를 얻고 **첫 글자 0.6~1.0초와
  답변의 자연스러움을 내줬습니다**(§6-나). 되돌리려면
  `RENDER_TRANSPORT_LIST = False` 한 줄이고, 그러면 `gpt-4o-mini` 의 정확도가
  위 표에서 다시 내려갑니다.
