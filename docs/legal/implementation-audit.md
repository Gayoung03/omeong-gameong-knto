# 약관·개인정보 처리 구현 점검

- 점검일: 2026-09-15
- 범위: 모바일·웹 앱, 관리자 웹, API, DB 모델, 이미지 저장소, AI·지도·메일·푸시 연동

## 이번에 문서에 반영한 사항

- 모바일 앱뿐 아니라 웹 서비스에도 적용되도록 범위를 수정했다.
- 현재 로그인 화면에서 소셜 로그인을 제공하지 않는 상태를 반영했다.
- 실시간 GPS는 수집하지 않지만 이용자가 입력한 출발지·숙소·장소의 주소와 좌표를
  처리한다는 점을 구분했다.
- 여행 일정, 직접 등록 장소, 리뷰, 여행 기록, 문의, 알림 등 실제 처리 항목을 추가했다.
- AI 챗봇 외에도 여행 요청 해석·일정 편집·설명, 선택 사진 기반 AI 카드 및 관리자 문의
  답변 초안에 OpenAI가 사용되는 점을 반영했다.
- 서버·DB, 이미지, 웹, 이메일, 푸시, 카카오 연동의 처리 위탁과 국외 처리 가능성을 기재했다.
- 웹의 브라우저 저장소와 일정 공유 링크 노출 범위를 반영했다.
- 특정 관광 데이터 제공기관 명칭을 이용약관에서 제거하고 공공·개방 데이터로 표현했다.

## 배포 전 추가 구현·운영 확인이 필요한 사항

1. **필수·선택 동의 이력 서버 저장**
   가입 화면의 동의 내역과 약관 버전은 현재 단말기 저장소 중심으로 관리된다. DB의
   `user_consents`와 가입 API를 연결하여 회원·약관 버전·동의 시각·철회 이력을 서버에
   남겨야 한다.
2. **탈퇴 후 30일 정리 작업**
   탈퇴 API는 계정 접근 차단과 챗봇 대화 삭제를 수행하지만, 나머지 개인정보의 30일 후
   삭제·익명화를 수행하는 정기 작업은 확인되지 않았다. 배치 작업과 운영 모니터링이 필요하다.
3. **업로드 이미지 파기**
   여행 기록·리뷰 등을 DB에서 삭제해도 S3 객체를 즉시 삭제하지 않는 경로가 있다.
   고아 파일 정리 작업과 백업 보유 주기를 확정해야 한다.
4. **국외 이전 고지·동의 절차**
   AI, 푸시, 이메일 등 실제 운영에 활성화한 사업자와 리전을 배포 환경에서 재확인하고,
   가입 또는 해당 기능 실행 전에 필요한 고지·동의 화면을 법률 검토 후 적용해야 한다.
5. **정책 게시와 변경 이력**
   시행일 전에 앱·웹에서 동일한 전문을 접근 가능하게 하고, 이후 개정본과 이전 버전을
   보관하며 중요한 변경은 공지·개별 통지할 수 있어야 한다.

이 문서는 구현 점검 기록이며 법률 자문을 대체하지 않는다. 실제 사업자 정보, 서버 리전,
보유 기간과 출시 기능을 확정한 뒤 개인정보 보호 담당자 또는 법률 전문가의 최종 검토를
받아야 한다.
